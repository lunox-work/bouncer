Implement the ticket in `ticket.md`, with your own tests.

- The interface is drafted in `src/solution.py`, with bodies that raise
  `NotImplementedError("not implemented")`. Keep its names and signatures.
- The task's code lives under `src/`. Change it and add new modules there.
  The standard library only.
- Write your tests under `tests/own/`, as `test_*.py` files of plain pytest
  functions that import from `src.solution`. `python3 sandbox/run.py own`
  runs them.
- Everything else (`sandbox/`, `.venv/`, `pytest.ini`, `requirements.txt`)
  is harness, and a submission that changes any of it is rejected.
- Acceptance is decided by a separate run of your code against tests that
  are not in this directory; your own tests are not part of it.
- There is no network and nothing to install.

Stop when you consider the ticket implemented. End with a short summary of
what you built.
